# 站点经验

踩过一次的站点，把结论记在这里。开工前先看一眼有没有现成的，省掉重新试参数那一轮。

一个文件一个站点，文件名用域名（`dpreview.com.md`）。

## 模板

```markdown
# <域名>

实测日期：YYYY-MM-DD

- **模式**：headless / 必须 --headed
- **参数**：需要的额外开关，写成能直接粘的命令
- **正文选择器**：从哪个节点取内容
- **要等什么**：骨架元素、关键选择器，或 --unblock 的毫秒数
- **坑**：下次会绊到的具体一条
```

只写"现在该怎么做"。故障经过、试错过程、被否掉的方案不写进来——它们对下一次没有用处，只会让这个文件越来越难扫。

结论过期了就改，不要在旁边补一条"以前是 X 现在是 Y"。
