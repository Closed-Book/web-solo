# zhihu.com

实测日期：2026-09-22

**同一个站，不同页面的防护强度不一样。** 这条是知乎给的最有用的经验：不要用"知乎能不能抓"这种二元判断。

| 页面 | 能过的档位 | 拿到多少 |
|---|---|---|
| 首页 `https://www.zhihu.com/` | 第 1 档 headless | 459 字符 |
| 热榜页 | 第 2 档（有头 + `--unblock 20000`）**仍然过不了** | 29 字符，title 为 `安全验证 - 知乎` |

- **模式**：首页 headless 即可。热榜页当前无解，按第 3 档处理——换源，或让使用者自己打开。
- **参数**：

  ```bash
  python3 scripts/browser.py fetch https://www.zhihu.com/
  ```

- **正文选择器**：整页 `body` 的 innerText。首页只有 459 字符，是登录引导 + 少量推荐条目，**不是完整内容流**——知乎的正文大头在登录态后面。
- **要等什么**：首页不用等，`domcontentloaded` 就够。
- **坑**：
  - 知乎对普通 HTTP 抓取（不带浏览器的那种）直接 403，所以这里 459 字符已经是"过了检测层"的结果，别拿它跟 403 比较后就以为抓全了。
  - 热榜的失效信号是 `title` 出现 `安全验证 - 知乎` 且 `text_len` 只有几十。看到这个就停：实测试过 `--unblock 20000`，页面停在安全验证上没动——这类验证等的是人去点，不是等时间，继续加时长不该是默认动作。
  - 首页能过**不代表**内页能过。每换一类页面重新按三档走一遍。
